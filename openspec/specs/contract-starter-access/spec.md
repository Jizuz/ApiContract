## 能力概述
契约网关能力以 Starter 形式交付：业务应用按 Provider 或网关角色引入对应 Starter，仅需"接口标注、白名单、实现类"三步完成接入，自动装配开箱即用，任意内置组件可被业务替换；面向业务后端开发者角色。

## 业务前置条件
- 业务应用运行于 Spring Boot 3 环境
- 编译开启 `-parameters` 参数（否则参数名丢失导致取值失败，缺失时启动告警）
- 注册中心客户端版本由业务统一管理（Starter 以可选方式声明依赖）
- 网关与 Provider 依赖同一版本的契约定义模块（版本由 BOM 统一管理）

## 输入定义
| 名称 | 类型 | 是否必填 | 说明 |
| ---- | ---- | -------- | ---- |
| 模块依赖 | 构件依赖 | 是 | 契约定义模块（api）、Provider Starter、网关 Starter、BOM 四件套 |
| 能力总开关 | 配置项 | 否 | 默认开启；关闭后不装配契约能力 |
| 泛化入口路径 | 配置项 | 否 | 默认 `/_contract/rpc`，可配置避让业务路径 |
| 白名单路径 | 配置项 | 否 | 默认 `META-INF/export.txt` |
| 白名单快速失败 | 配置项 | 否 | 默认开启（解析失败中断启动） |
| 元数据发布方式 | 配置项 | 否 | 默认配置中心模式，可回退实例元数据/仅日志 |
| 调用器模式 | 配置项 | 否 | 默认字节码，可切回反射 |
| 默认序列化 | 配置项 | 否 | 默认 json |
| 负载均衡策略 | 配置项 | 否 | 默认轮询 |
| 集群策略 | 配置项 | 否 | 默认 failover |
| 路由链 | 配置项 | 否 | 默认版本路由+标签路由 |
| 调用超时 | 配置项 | 否 | 默认 3000ms，契约级可覆盖 |
| 重试次数 | 配置项 | 否 | 默认 2 |
| 实例兜底校准周期 | 配置项 | 否 | 默认 10s |
| 空实例缓存时长 | 配置项 | 否 | 默认 1s |
| 连接池参数 | 配置项 | 否 | 最大连接（默认500）、空闲时间（默认30s）、获取等待超时（默认1000ms） |
| 熔断参数 | 配置项 | 否 | 失败率阈值（默认0.5）、最小请求数（默认20） |

## 输出定义
| 名称 | 类型 | 说明 |
| ---- | ---- | ---- |
| 自动装配的契约能力 | 运行时能力 | 无需业务添加任何启用注解 |
| 可替换的内置组件 | 容器组件 | 全部内置组件声明可替换，业务可覆盖任意实现 |
| 发布自检日志 | 结构化日志 | 契约就绪、元数据发布、实例注册三项成功记录 |

## 主流程（正向链路）
1. 业务依赖契约定义模块，在接口方法上标注契约标识。
2. 依赖 Provider Starter。
3. 在 `META-INF/export.txt` 写入需暴露的接口全限定名。
4. 实现接口并声明为普通 Bean。
5. 启动应用，确认自检日志中契约就绪、元数据发布、实例注册三项均成功。
6. 前端侧接入：拼接 `?mt={契约标识}` 并携带契约参数，无需感知服务名与路径。

## 分支场景
- 角色拆分：默认推荐 Provider Starter 与网关 Starter 两个独立 Starter（依赖隔离）；单一 Starter 形态可按角色配置切换
- 空白名单：不发布契约、不注册泛化入口，应用正常启动
- 未引入异步客户端依赖：降级为同步实现并告警，功能不缺失
- 单机调试模式：关闭注册中心发布，网关直连本地实例（本地开发、联调）
- 序列化依赖复用容器内已有组件，不强制引入额外 JSON 库

## 异常场景 & 业务错误码
| 场景 | 错误码 | 业务表现 |
| ---- | ------ | -------- |
| 能力总开关关闭 | - | 契约能力不装配，应用按普通应用启动 |
| 依赖的注册中心组件缺失 | - | 条件装配不生效并给出明确提示 |
| 泛化入口路径与业务路径冲突 | PATH_CONFLICT | 启动报错，提示通过配置修改入口路径 |
| 编译参数缺失 | PARAM_NAME_MISSING | 启动告警并提示开启 `-parameters` |

## 数据约束
- 必须开启 `-parameters` 编译参数
- 网关与 Provider 依赖同一版本契约定义模块；发布前完成兼容性检查
- 契约方法禁止重载
- 白名单不跨 jar 合并，公共契约由业务自行列入
- 注册中心客户端版本由业务统一管理

## 权限与数据隔离
- Provider 与网关 Starter 依赖隔离，互不串扰
- 全部内置组件可替换（声明可覆盖），业务可按需定制

## 并发与重试规则
- 自动装配为启动期一次性动作，运行期不变更

## 业务容量约束
- 无独立业务容量约束（继承各能力规格约束）

## 验收用例（测试要点）
✅ 正向用例
- 三步接入（接口+白名单+实现类）零额外配置，自检日志三项成功
- 前端拼接 `?mt=` 即可调用成功
- 任意内置组件被业务替换后正常生效

🔄 边界用例
- 独立网关与单机调试两种形态均可完成接入验证
- 空白名单应用正常启动
- 未引入异步依赖时降级同步并告警

❌ 异常用例
- 路径冲突启动报错且可通过配置规避
- 参数名缺失启动告警
- 版本不一致在发布前兼容性检查中被发现

## 兼容与灰度规则
- BOM 统一版本管理，发布前兼容性检查
- 各配置项默认值即可运行，灰度通过配置项与 SPI 组合实现

## 业务埋点与告警指标
- 发布自检日志（export loaded / contract ready / meta published / registry joined）作为上线验收依据
- 组件覆盖清单启动日志

## 规格备注
- 本能力是全部能力对业务的交付形态；对应工程模块四件套（api / provider-starter / gateway-starter / bom）
- 部署形态已确认：独立网关为默认形态，保留单机调试模式；内嵌网关本期不做
