## 能力概述
网关到 Provider 的调用链路全异步非阻塞、连接复用，配套三级超时、契约+实例维度熔断、契约级限流、有界背压与调用过滤器链，保障单个慢契约或故障实例不拖垮网关整体；面向网关运维与后端开发者角色。

## 业务前置条件
- 异步客户端能力就绪；未引入时自动降级为同步实现并告警
- 连接池、超时、熔断、限流参数已按配置项就绪
- 过滤器链顺序按 order 生效（trace、日志、指标；鉴权过滤器本期不做、仅预留扩展点）

## 输入定义
| 名称 | 类型 | 是否必填 | 说明 |
| ---- | ---- | -------- | ---- |
| 调用上下文 | 契约调用请求 | 是 | 目标契约、实例、参数数组、traceId |
| 超时配置 | 配置项 | 否 | 连接超时、读超时、整体调用超时三级；契约级可覆盖全局默认 |
| 熔断配置 | 配置项 | 否 | 失败率阈值、统计最小请求数 |
| 限流配置 | 契约级配置 | 否 | 契约级限流策略与阈值 |

## 输出定义
| 名称 | 类型 | 说明 |
| ---- | ---- | ---- |
| 异步调用结果 | 非阻塞返回 | 成功结果或统一错误结构 |
| 稳定性动作 | 运行时行为 | 熔断打开/半开探测恢复、快速失败、限流拒绝、failover 换实例 |
| 可观测数据 | 日志/指标 | 契约维度 QPS、RT、错误率、熔断次数、重试次数、连接池使用率 |

## 主流程（正向链路）
1. 网关请求线程只做解析与参数组装。
2. IO 与等待由事件循环承担，按目标地址维度复用长连接。
3. 回调线程完成结果封装与返回（回调中禁止执行阻塞操作）。
4. 按契约 + 实例维度统计失败率，超过阈值短路返回，半开探测恢复。
5. 全链路 traceId 透传至 Provider，两侧日志可关联。

## 分支场景
- 未引入异步客户端依赖：降级为同步实现并告警，功能不缺失
- 连接池等待队列有界：超限快速失败，不无限排队放大
- 不同契约共享连接池，但限流与熔断相互独立
- 实例刷新失败沿用最近一次快照，不清空

## 异常场景 & 业务错误码
| 场景 | 错误码 | 业务表现 |
| ---- | ------ | -------- |
| 连接池耗尽（获取连接超时） | UPSTREAM_UNAVAILABLE | 快速失败并返回明确错误码，不排队放大 |
| 熔断打开 | CIRCUIT_OPEN | 短路返回，半开探测后恢复 |
| 调用超时 | TIMEOUT | 三级超时控制（连接/读/整体），契约级覆盖 |
| 单个实例异常 | INVOKE_ERROR / UPSTREAM_UNAVAILABLE | failover 换实例重试；超阈值熔断该实例 |
| 回调线程阻塞 | -（禁止项） | 属使用约束违例，需在评审与测试中拦截 |

## 数据约束
- 熔断统计维度：契约 + 实例（非全局一刀切）
- 空实例结果短时缓存（默认 1 秒）防击穿
- 错误响应不含内部堆栈

## 权限与数据隔离
- 本期不做鉴权（已确认决策），过滤器链内置 trace、日志、指标，鉴权扩展点预留
- 契约级限流实现契约间隔离，防单契约拖垮整体

## 并发与重试规则
- 重试由集群策略统一控制（failover/failfast/failsafe），重试不绕过路由链
- 写类契约重试场景由业务保证幂等
- 调用链顺序固定：路由 → 限流 → 负载均衡 → 调用 → 容错

## 业务容量约束
- 连接池参数：最大连接数、每主机连接上限、最大空闲时间、获取连接等待超时（均有界）
- 网关单机 QPS 不低于优化基线 1.5 倍；P99 超时率低于 0.1%
- 连接复用率达标，连接创建速率稳定

## 验收用例（测试要点）
✅ 正向用例
- 稳态压测下连接复用稳定、无频繁建连抖动
- 契约级超时、熔断阈值正确触发与恢复（半开探测）
- 契约维度指标（QPS/RT/错误率/熔断/重试/连接池使用率）可观测

🔄 边界用例
- 未引入异步依赖时降级同步并告警，功能不缺失
- 慢契约高并发下其他契约不受影响（限流与熔断独立）
- 实例刷新失败沿用快照继续服务

❌ 异常用例
- 单实例异常触发 failover 换实例，超阈值后该实例被熔断
- 连接池耗尽快速失败返回明确错误码，不雪崩
- 三级超时各级独立生效
- 各故障场景均可降级，不引发整体不可用

## 兼容与灰度规则
- 三级超时统一配置，契约级覆盖默认值
- 熔断参数可调，支持运行期策略调整

## 业务埋点与告警指标
- 告警：熔断打开、连接池耗尽、超时率异常、失败率异常
- 指标：契约维度 QPS、RT、错误率、熔断次数、重试次数、连接池使用率

## 规格备注
- 对应实施方案阶段四（异步与稳定性），建议在阶段三完成后经全链路压测确认收益再推进
- 与 `contract-gateway-routing`（调用链顺序约束）、`contract-spi-extension`（策略扩展）关联
