## 能力概述
契约调用链支持 JSON 与 Protobuf 两种序列化形态：前端↔网关固定 JSON（已确认决策），网关↔Provider 按契约元数据声明的序列化方式编解码，支持全局/服务/契约三级配置与按契约粒度灰度切换、独立回退。

## 业务前置条件
- 契约元数据已声明序列化方式（默认 json）
- 二进制形态启用前，契约的 Protobuf schema 已随契约定义模块同版本发布（不经配置中心传输）
- 网关与 Provider 对同一契约的序列化方式声明一致（启动校验）

## 输入定义
| 名称 | 类型 | 是否必填 | 说明 |
| ---- | ---- | -------- | ---- |
| 序列化方式声明 | 契约元数据字段 | 是 | json / protobuf；契约级覆盖服务级，服务级覆盖全局默认 |
| schema 引用 | 契约元数据字段 | protobuf 时必填 | 与契约接口同包、同版本分发的 schema 引用 |
| 待编码内容 | 参数数组/返回结果 | 是 | 按契约参数顺序或返回类型组织 |

## 输出定义
| 名称 | 类型 | 说明 |
| ---- | ---- | ---- |
| 编码后请求体 | 内容流 | 网关→Provider 方向的参数数组编码 |
| 编码后响应体 | 内容流 | Provider→网关方向的返回结果编码 |
| 前端侧响应 | JSON | 恒为 JSON（网关完成形态转换，前端零感知） |

## 主流程（正向链路）
1. 契约先以 JSON 上线并完成业务验证。
2. 为契约补充 Protobuf schema，接口与 DTO 定义不变。
3. 契约元数据声明切换为 protobuf，网关与 Provider 同时按新方式编解码。
4. 调用链路按元数据声明选择编解码器（网关据 schema 引用选择对应二进制编解码）。
5. 出现问题时按契约粒度回退 JSON，不影响其他契约。

## 分支场景
- 全局默认 json；服务级声明；契约级覆盖（三级优先级：契约 > 服务 > 全局）
- 前端侧恒为 JSON：Content-Type 协商仅作用于网关↔Provider 链路
- 联调、内部后台等场景始终使用 JSON（可读、抓包可解析）

## 异常场景 & 业务错误码
| 场景 | 错误码 | 业务表现 |
| ---- | ------ | -------- |
| 请求体编解码失败 | SERIALIZE_ERROR（网关侧）/ CONTRACT_INTERNAL_ERROR（Provider 侧） | 返回明确错误码，禁止降级为静默空结果 |
| 两侧序列化声明不一致 | SERIALIZER_MISMATCH | 启动校验失败，不允许以不一致状态上线 |
| schema 缺失或引用无效 | SCHEMA_REF_INVALID | 契约不可启用二进制，启动校验报错 |

## 数据约束
- schema 字段编号一次性分配，禁止复用
- 删除字段只允许标记废弃并保留编号
- schema 与契约标识的对应关系写入元数据 schemaRef 字段
- schema 随契约定义模块依赖分发，同一版本强一致

## 权限与数据隔离
- 序列化方式按契约粒度隔离，单契约切换不影响其他契约

## 并发与重试规则
- 切换期间以元数据声明为准，两侧同步生效，不出现半新半旧混跑
- 编解码失败不重试编解码，直接返回错误码

## 业务容量约束
- 二进制形态用于高频调用、嵌套对象、大返回体契约（包体积与编解码开销下降）
- 单服务二进制契约比例无硬性限制，按契约逐一灰度

## 验收用例（测试要点）
✅ 正向用例
- 单契约由 JSON 切换 protobuf 后调用成功，且其他契约不受影响
- 契约粒度回退 JSON 后立即恢复调用
- 嵌套对象、大返回体契约在二进制形态下字节量与编解码耗时可测量下降

🔄 边界用例
- 三级优先级（契约>服务>全局）声明组合正确生效
- schema 废弃字段（deprecated 保留编号）新旧两侧兼容解析
- 前端侧始终收到 JSON，切换无感知

❌ 异常用例
- 编解码失败返回明确错误码，无静默空结果
- 两侧声明不一致时启动失败
- schema 引用无效时契约不可启用二进制

## 兼容与灰度规则
- 灰度顺序固定：JSON 上线 → 验证 → 补 schema → 元数据声明切换 → 可按契约粒度回退
- 前端联调阶段保留 JSON（已确认决策：前端不解析二进制）

## 业务埋点与告警指标
- 契约序列化方式分布（json/protobuf 占比）
- 编解码失败率按契约维度统计与告警

## 规格备注
- 受提案决策约束：Protobuf 仅用于网关↔Provider 内部链路，前端入口固定 JSON
- 与 `contract-metadata`（声明载体）、`contract-provider-invoke` / `contract-gateway-routing`（编解码执行方）关联
